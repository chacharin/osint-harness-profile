# Sub-skill 4: Executive_Reporting
(การจัดทำรายงานสำหรับผู้บริหารฝ่ายความมั่นคง)

## When to Use
- เมื่อผู้บังคับบัญชาสั่ง "ต่อไป" หรือ "next" หลังรายงานขั้นที่ 3 (ขั้นที่ 4 ซึ่งเป็นขั้นสุดท้ายของ Pipeline ใน intelligence-analyzer)
- เมื่อผู้บังคับบัญชาสั่งแก้รายงานของขั้นที่ 4

**หน้าที่:** สรุปผลการวิเคราะห์ทั้งหมดให้อยู่ในรูปแบบรายงานที่กระชับ อ่านง่าย และพร้อมสำหรับการตัดสินใจระดับบริหาร (Executive Summary) บันทึกลง workspace ส่วนกลาง แล้วแจ้งชื่อไฟล์ต่อผู้บังคับบัญชา

## Procedure

### 1) เปิดแฟ้มงานเดิม
1. ใช้แฟ้มงานเดิมของภารกิจตามข้อ 6.3 ของ intelligence-analyzer
2. อ่าน `step1.md`, `step2.md`, `step3.md` ในแฟ้มงานด้วย `read_file` หากไฟล์ใดไม่มี ให้หยุดและแจ้งผู้บังคับบัญชา

### 2) กำหนดวันเวลารายงานและชื่อไฟล์
1. อ่านเวลาไทยด้วย `terminal`: `TZ=Asia/Bangkok date +%d-%m-%Y_%H-%M`
2. ตั้งชื่อไฟล์ `report_[DD-MM-YYYY]_[HH-MM].md` เช่น `report_18-10-2026_11-05.md`
3. หากชื่อนั้นมีอยู่แล้วใน workspace ส่วนกลาง ให้เลื่อนเวลาไปทีละ 1 นาทีจนไม่ซ้ำ
4. ใช้วันเวลาเดียวกับชื่อไฟล์ใส่ใน REPORTED DATE และ REPORTED TIME (แสดงเวลาในรายงานเป็น HH:MM)
   - กรณีผู้บังคับบัญชาสั่งแก้ขั้นที่ 4 ให้เขียนทับไฟล์รายงานเดิม ไม่ต้องสร้างชื่อใหม่

### 3) เรียบเรียงรายงาน
- ใช้เฉพาะเนื้อหาจาก `step1.md`–`step3.md` ห้ามเพิ่มข้อเท็จจริงหรือแหล่งใหม่ในขั้นนี้
- **ภาพรวมสถานการณ์** มาจากขั้นที่ 1
- **ผลการวิเคราะห์ผลกระทบเชิงลึก** เลือกเฉพาะมิติ STEEPM ที่มีนัยสำคัญสูงจากขั้นที่ 3
- **ผลการประเมินความเสี่ยง** มาจากตารางความเสี่ยงและโอกาสของขั้นที่ 3
- **การประเมินความน่าเชื่อถือของแหล่งอ้างอิง** มาจากขั้นที่ 2
- **ช่องว่างของข้อมูล** มาจากขั้นที่ 3
- **ข้อเสนอแนะ** ต้องเป็นการดำเนินการที่ปฏิบัติได้ และโยงกับความเสี่ยงหรือช่องว่างที่ระบุไว้ (อ้างรหัส RISK 1/GAP 1)

### 4) การอ้างอิงแบบ APA7
1. เขียนรายงานแบบ APA7 และอ้างอิงในเนื้อหาทุกคำกล่าวอ้าง เช่น (กระทรวงการต่างประเทศ, 2026) หรือ (Reuters, 2026)
2. แปลงรหัส `[SOURCE x]` เป็นการอ้างอิงในเนื้อหาแบบ APA7 ไม่ต้องแสดงรหัส `[SOURCE x]` ในรายงาน
3. รูปแบบรายการอ้างอิง: ผู้แต่ง/หน่วยงาน. (ปี, เดือน วัน). *ชื่อเรื่อง*. ชื่อเว็บไซต์. URL
   - ไม่มีวันที่เผยแพร่ ใช้ (n.d.) สำหรับภาษาอังกฤษ หรือ (ม.ป.ป.) สำหรับภาษาไทย
4. รายการอ้างอิงต้องมีเฉพาะแหล่งที่ถูกอ้างในเนื้อหา และทุกการอ้างในเนื้อหาต้องมีในรายการอ้างอิง
5. เรียงรายการอ้างอิงตามตัวอักษร

### 5) เขียนไฟล์และตรวจทาน
1. เขียนรายงานลง `<workspace>/report_[DD-MM-YYYY]_[HH-MM].md` ด้วย `write_file` (อยู่ workspace ส่วนกลาง **ไม่อยู่ในแฟ้มงาน**)
2. เขียน `<แฟ้มงาน>/step4.md` ตามแบบฟอร์มด้านล่าง
3. ตรวจคำสะกดด้วย `proofread_thai` กับไฟล์รายงานและ `step4.md` (ห้ามรับการแก้ที่เปลี่ยนชื่อเฉพาะ ชื่อเรื่องของแหล่ง หรือ URL)
4. ตรวจตามรายการ Verification ทุกข้อ แล้วบันทึกผลลง `step4.md`

### 6) รายงานต่อผู้บังคับบัญชา
แสดงผลตามรูปแบบนี้ แล้วสิ้นสุดภารกิจ:

```
เรียน ผู้บังคับบัญชา

ขั้นที่ 4/4: Executive_Reporting
แฟ้มงาน: <ชื่อแฟ้มงาน>
ไฟล์รายงาน: report_DD-MM-YYYY_HH-MM.md (workspace ส่วนกลาง)
ไฟล์ผลลัพธ์ขั้นที่ 4: <ชื่อแฟ้มงาน>/step4.md

<เนื้อหารายงานฉบับเต็ม>

ผลการตรวจคำสะกด: <สรุปผลจาก proofread_thai>

ครับ
จบภารกิจ
```

## Pitfalls
- **เพิ่มข้อมูลใหม่ในรายงาน:** ขั้นนี้เป็นการเรียบเรียงเท่านั้น ข้อเท็จจริงที่ไม่มีใน `step1.md`–`step3.md` ห้ามใส่
- **การอ้างอิงไม่ตรงกัน:** การอ้างในเนื้อหาที่ไม่มีในรายการอ้างอิง หรือรายการอ้างอิงที่ไม่ถูกอ้างในเนื้อหา ถือว่าไม่ผ่าน
- **วางไฟล์รายงานผิดที่:** `report_*.md` ต้องอยู่ workspace ส่วนกลาง ส่วน `step4.md` อยู่ในแฟ้มงาน
- **ใช้เครื่องหมาย `:` ในชื่อไฟล์:** ชื่อไฟล์ใช้ `HH-MM` เสมอ (ใช้ `HH:MM` ได้เฉพาะในเนื้อหารายงาน)
- **ปิดท้ายผิด:** ขั้นที่ 4 ต้องปิดด้วย "ครับ" ตามด้วย "จบภารกิจ" ห้ามใช้บรรทัดรอคำสั่งของขั้นที่ 1–3
- **ละเมิด OPSEC:** ข้อเสนอแนะต้องไม่เปิดเผยจุดอ่อนหรือกลยุทธ์ภายในของหน่วยงานฝ่ายตนเอง

## Verification

- [ ] ไฟล์รายงานอยู่ workspace ส่วนกลาง และชื่อไฟล์ตรงกับ REPORTED DATE และ REPORTED TIME
- [ ] รายงานมีครบทุกหัวข้อตามลำดับในแบบฟอร์ม
- [ ] ทุกคำกล่าวอ้างมีการอ้างอิง APA7 และการอ้างในเนื้อหากับรายการอ้างอิงตรงกันครบทุกรายการ
- [ ] ข้อเสนอแนะทุกข้อโยงกับรหัสความเสี่ยงหรือช่องว่างของข้อมูล
- [ ] มี `step4.md` ในแฟ้มงาน
- [ ] รัน `proofread_thai` กับไฟล์รายงานและ `step4.md` แล้ว
